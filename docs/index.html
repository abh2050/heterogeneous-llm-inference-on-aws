EVIDENCE BOUNDARIES

Measured, calculated, and still uncertain

MEASURED

Direct observations

TTFT, ITL, throughput, KV pool, engine comparison, router overhead, and mixed-workload behavior for this exact setup.

CALCULATED

Derived from measurements

Cost per million output tokens, speedup ratios, the 70% load point, and the 85× TTFT improvement.

ESTIMATED

Useful sanity checks

Roofline ceilings and theoretical compute or bandwidth explanations. These are not capacity commitments.

Limits you should say out loud

  • One small model and one precision were tested.
  • The final mixed-workload conditions were run once; variance is unknown.
  • CPU sweep runs were short, so their capacity values are upper bounds.
  • The router and two benchmark clients shared the four-vCPU GPU host.
  • Traffic stayed inside one VPC and one AWS region (`us-east-2`).
  • Autoscaling, multi-AZ failover, rolling releases, and sustained observability were not tested.
  • Prices are the experiment inputs, not current AWS quotes.

FURTHER READING

The papers behind the stack

  1. PagedAttention — explains the block-based KV memory design that made vLLM practical at high concurrency.
  2. Orca — introduced iteration-level scheduling, the foundation of continuous batching.
  3. Sarathi-Serve — studies chunked prefill and the trade between throughput and decode stalls.
  4. DistServe — separates prefill and decode so each phase can scale for its own bottleneck.
  5. Splitwise — explores phase splitting across heterogeneous hardware and its system-level tradeoffs.
